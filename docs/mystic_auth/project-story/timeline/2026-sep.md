### Commit 71: 4 September, 2026

`5aff4be`: "Blocked self-role privilege escalation, patched security headers and Docker images"

Security hardening driven by a manual adversarial pentest by Claude Code and an automated audit scan (Bandit/ZAP/testssl.sh/pip-audit/npm audit) against the local-prod-ngrok stack, both checked into the repo for reference.

- **The pentest's one real finding, fixed:** a caller holding only `users:assign_role` could relabel *themselves* to `admin` via `PATCH /users/{email}/role` or its bulk counterpart. Not exploitable today (nothing branches on `role == "admin"`), but a real escalation path waiting for the first downstream shortcut that does. Now rejected outright (`403 CANNOT_CHANGE_OWN_ROLE`), with regression tests.
- `COOP`/`CORP`/`COEP` added on backend and nginx; frontend CSP tightened; HSTS moved onto the real TLS terminator; `nginx server_tokens off`.
- Base images bumped and pinned to patched tags; `pip`/`setuptools` stripped from the backend runtime image entirely.
- Per-endpoint rate-limit overrides added, closing a tracked gap; Windows entry points added for two scripts still missing them; the project-story timeline split into smaller per-month files.

### Commit 72: 5 September, 2026

`4238bde`: "Ran security audit, migrated backend to Alpine, fixed entrypoint and token leak"

A live security audit (Bandit, Semgrep, Trivy, gitleaks, pip-audit, npm audit, a full OWASP ZAP active scan, plus a manual adversarial pentest and a real-browser pass) against a running local-prod-ngrok deployment, re-run clean against a completely fresh rebuild of the stack, followed by fixing what it turned up.

- Backend base image migrated Debian to Alpine, taking Trivy from 57 High/Critical to 0 on the runtime image; a self-healing entrypoint replaced a manual post-migration volume-fix step.
- A real login-lockout race fixed: one atomic Redis `INCR` instead of a check-then-increment pair that let extra failed attempts through under a burst.
- A real token leak caught in manual review: Procrastinate's job-lifecycle logging was echoing each job's full arguments to stdout, including the raw verification/reset token in `send_email_task`'s email body. Fixed by raising that logger to `WARNING`.
- The real Caddy production TLS path tested for the first time, catching a duplicate `Strict-Transport-Security` header and a gap where the tunnel modes never sent HSTS on the frontend's own pages.
- Production scaling made configurable (`UVICORN_WORKERS`/`DB_POOL_SIZE`/`DB_MAX_OVERFLOW`); CSP `style-src` dropped `unsafe-inline`; an optional off-host backup upload hook added.
- Full audit re-run clean against the rebuilt images (Bandit/Semgrep/Trivy/pip-audit/npm audit/Gitleaks/ZAP), a fresh manual pentest (17/17 attempts blocked), and a load test finding the real throughput ceiling (~520-560 req/s, Postgres pool saturation past 1,000 concurrent).
