# How It Evolved: November 2026

---

### Commit 84: 5 November, 2026

"Added passkeys and fixed Claude Code security audit findings"

- Added optional passkey (WebAuthn) sign-in and management: single-use challenges in PostgreSQL, a per-IP lockout with a security alert, a 15-minute step-up check (password, existing passkey, or Google) before changes, a Passkeys tab with bulk removal, owner email notices on every add and remove, and a `users:manage_passkeys` permission for incident-response removal.
- Added passkey events to the Security Log, Rate Limits, and all four languages, with backend, component, and virtual-authenticator browser tests.
- Ran two Claude Code security audits and fixed their findings: a `user_management` holder taking over admin accounts, superuser database credentials in backend and worker environments, the public readiness endpoint, NUL-byte 500s in the bulk endpoints, signup email throttling, `Cache-Control: no-store` on API responses, secret env files losing mode 600 on field edits, and a per-account failed-login cool-down across IPs that raises an alert.
- Made `security_audit_log` and `authorization_audit_log` append-only: stopped anonymizing them on account deletion and purge, removed the retention job and `AUDIT_LOG_RETENTION_DAYS`, and revoked `DELETE` and `UPDATE` from the runtime database role.
- Added a self-hosted ntfy alert channel with a setup script, ran Valkey as a non-root user, and acted on Docker Bench and Lynis scans.
- Changed the sync ownership guard to merge upstream fixes to seeded starter files (`app_sdk.*`, `models.py`, `main.tsx`, `theme.ts`, app READMEs) three-way, and fixed the apply stage failing on an empty net diff, with regression tests.
- Reworked the upstream sync after running it on a real downstream app so one short prompt can drive it: the script now stops with the exact refresh command when its own tools are out of date, stages its result and never commits, skips files already identical to upstream, and has `--abort`, which explains in plain words what it will undo and waits for a typed `abandon`. The sync agent prompt became six steps that end with the full CI run and a separate report of MysticAuth issues, with new regression tests for each behavior.
- Made the template buildable from `app/` alone with an app-owned `models.py`, a fixed `sdk.py`/`sdk.ts` export list, and `app_sdk.*` for any other `mystic_auth` import, with guard tests.
- Restructured the backend and frontend into domain packages: `api/` holds only routes, one `middleware/` package, `user_session/` and `refresh_token_logic/` modules, and frontend folders per domain.
- Added an optional `EMAIL_LOGO_PATH`, a skip link, a route-title announcer, and screen reader tests, and made the access dialog tabs render only while active after measuring INP with new `measure-inp.mjs` and `lighthouse-flow.mjs` scripts.
- Made the policy details Edit tab look and behave as disabled for protected baseline and system policies.
- Limited the backup script's empty-database check to the application database, since `bugsink` is empty until its service starts.
- Reorganized the deployment docs, added a threat model and flow diagrams, and removed references to non-public material.
- Trimmed long comments across code, tests, scripts, and Compose files, and removed dead code and unused translation keys.
- Bumped `pydantic` patch versions and refreshed the third-party license notices.
