### Commit 79: 8 October, 2026

"Made token revocation durable, added lifecycle event queue, backup HMAC verification"

- Added PostgreSQL-backed token-revocation versions so logout-all, password changes, deletion, and purge invalidate existing tokens across processes and workers.
- Added a transactional account-lifecycle event queue with durable snapshots, reconciliation, retries, and at-least-once delivery.
- Added app-owned worker and listener hooks, a downstream secret-provider boundary, and public policy and user SDK APIs without leaking credentials or creating SDK import cycles.
- Added detached HMAC-SHA256 backup verification, production backup preflights, and Compose support for both Bash and Windows PowerShell workflows.
- Hardened CI with action pinning, image digest, log rotation, read-only filesystem, path, and sync ownership guards.
- Fixed downstream sync behavior for protected root docs, upstream script renames, missing three-way patch bases, unstaged app work, failed stash restoration, and recovery of a sync tool kept only in a stash, with regression coverage for the sync paths.
- Fixed backup and GeoIP deployment defaults. Development now declares the MaxMind credential fields and fails before startup when GeoIP is enabled without them, instead of leaving readiness stuck behind a restarting updater.
- Updated lifecycle, worker, integration, backup, deployment, security, template, testing, and project-story documentation, including the downstream review and recovery workflow.
- Removed downstream-sensitive test literals: browser and status-page checks now follow configured `APP_NAME`, while backup and restore regressions follow configured `POSTGRES_DB`. This keeps downstream branding and database names compatible with upstream-owned tests.
